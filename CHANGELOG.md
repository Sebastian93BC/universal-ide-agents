# Changelog

Release journal for `universal-ide-agents`.

This file follows Semantic Versioning and records meaningful changes to the shared VS Code, Claude Code, and Antigravity asset library.

---

## 3.1.0 · 2026-11-25

Usable by people other than its maintainer.

### Changed

- **`plans/` is no longer versioned.** It is the maintainer's local task log, names projects and clients, and the repository is public; `.gitignore` now excludes it.
- **README rewritten**: what it is, how to install it in a project (submodule, profile, dry run, deploy, verify, guard, update, remove), how the repository is organized (`core/` vs. the generated `.agents/`, `.claude/`, `.github/`), how to work on it and how to configure the harvester. The technology overview and badges were removed.
- **Harvester configurable by anyone** (`scripts/harvest.py`): configuration from `--config`, `UIA_HARVEST_CONFIG` or `harvester/sources.local.json`; without one it stops and explains instead of scanning the example paths. New `--init` and `--check-config` (shows roots and candidate counts, writes nothing). `includePatterns` (alias of the old, previously ignored `targetPatterns`) now selects files, at any depth and per root; missing roots are reported; the repository never harvests itself. The example configuration is generic.
- **Local client terms**: `harvester/sanitization.local.json` (ignored) adds to the public `forbiddenClientTerms`; the validator, the scanner and the harvester use both. Client terms now match inside snake_case names.
- **The public client-term list is now empty**: it published the very names it protects. Maintainers keep theirs in `harvester/sanitization.local.json`; CI still blocks emails, tenant URLs, tokens, credentials and personal paths.
- **History rewritten** to remove `plans/`, the client-term list, personal paths and client paths from every commit; commit ids from before this release changed.

## 3.0.0 · 2026-11-25

Generic layer for projects generated by `template-data-flow-automation` (plan `005`).

### Breaking

- **Deployment no longer touches the project root.** `scripts/deploy-to-project.sh` is now a wrapper of `scripts/deploy.py` and writes only under `.agents/`, `.claude/` and `.github/`. It no longer copies `AGENTS.md`, `CLAUDE.md`, `.antigravity-instructions.md`, `.github/copilot-instructions.md`, `.github/hooks/`, `docs/` or `scripts/`, and no longer scaffolds `plans/`.
- **`--profile` now filters.** Only the agents, skills, rules and MCP servers of the requested profiles are deployed. `data-eng-mongodb` is replaced by `data-eng-base`; the default profile is `data-eng-base`.
- `--clean` is kept for compatibility; pruning what a previous deployment left behind is now the default and is limited to files listed in the manifest.

### Added

- **Deployment manifest** `.agents/universal-ide-agents.json` (version, profiles, date, deployed files, root file hashes). Redeploying with the same source changes nothing; files not owned by the deployment, or edited locally, stop the deployment (exit 2) unless `--force`.
- **Tool-agnostic profiles with `extends`**: `data-eng-base` (core, MongoDB, data modeling) plus `data-eng-n8n` or `data-eng-dagster-duckdb`, combinable (`--profile a,b`). `data-eng-lakehouse` and `data-eng-full` now extend them.
- **Three-level limits** (`core/rules/core/limites-tres-niveles.rule.md`): seven rules, each with one restriction, one reason and a mechanical check in the Claude Code `PreToolUse` guard `core/hooks/universal-ide-agents-guard.py`, deployed to `.claude/hooks/`.
- **Task-close mode for `knowledge-harvester`**: `knowledge-harvester cierre-tarea --tarea … --conocimiento-tarea … --conocimiento-proyecto …`, documented as the contract with `dfa task close` in `docs/contrato-template-dfa.md`.
- **`session-handoff` skill**: handoff note in the task before ending a session, for the next session or the other IDE.
- **Single verifier** `make check` (`scripts/check.py` + tests): core validity, compiled output in sync, no sync-conflict copies, one-line pointers, `AGENTS.md` line cap, skill `name` equals folder, profiles resolve, docs indexed and links alive, sensitive data. `check.py --project DIR` verifies a deployed project (manifest present, `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` unchanged).
- **Sensitive data scanner** `scripts/scan_sensitive.py` (emails, tenant URLs, GUIDs, token-shaped strings, credentials in URIs, personal paths, client names), run on every PR by `.github/workflows/check.yml`.
- `scripts/uia_lib.py`: one inventory and one compiler shared by build, deploy and check. Rules now require a valid Antigravity `trigger`; asset names must be unique across categories.

### Changed

- `CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md` are one-line pointers (`@AGENTS.md`); their content moved into `AGENTS.md`. `.antigravity-instructions.md` was removed (Antigravity does not read it).
- Hub-only assets moved to category `hub` and are never deployed: skills `knowledge-harvester` and `skill-creator`, rule `planning-and-versioning`.
- `planner` and `implementer` take the plan location from the project's `AGENTS.md` instead of assuming `plans/{slug}_plan.md`.
- Submodule instructions use HTTPS (`https://github.com/Sebastian93BC/universal-ide-agents.git`) in `.modules/universal-ide-agents`; anonymous clone verified.
- `harvester/sources.example.json` uses generic paths.

### Fixed

- Removed 60 sync-conflict duplicates (`SKILL 2.md`, `SKILL 3.md`, `* 3.py`) from the compiled folders; `.gitignore` and `make check` now catch them.

### Added

- **Periodic Knowledge & Skill Harvester (`scripts/harvest.py` & `harvester/`)**:
  - Incremental SHA-256 scanner across local project directories, course notes, and IDE memories (`~/.claude/projects/*/memory/`, `~/.gemini/antigravity-ide/knowledge/`).

- **11 Canonical Agents (`core/agents/`)**:

  - **Core Lifecycle**: `planner`, `implementer`, `code-reviewer`, `docs-steward`, `tdd-cycle`, and `knowledge-harvester`.
- **25 Modular Data Engineering & Core Skills (`core/skills/<category>/<name>/SKILL.md`)**:

  - **DuckDB / DuckLake, Lakehouse & CDC Streaming**: `duckdb-parquet-optimization` (*Min-Max Zone Maps* vs Hive over-partitioning, single-writer lock), `ducklake-medallion-architecture`, `mongodb-to-duckdb-cdc-offload` (`QUALIFY ROW_NUMBER()` deduplication & tombstones), `pyspark-delta-iceberg-lakehouse` (*Liquid Clustering*, *AQE*, *Deletion Vectors*, *CDF*), and `kafka-debezium-cdc-streaming` (log-based CDC, PK partitioning, `BACKWARD_TRANSITIVE` Schema Registry, Outbox Pattern, DLQ).
  - **Dagster & Orchestration**: `dagster-asset-architecture` (`dg.EnvVar`, `dg check defs`), `dagster-duckdb-dbt-integration` (`concurrency_key`), `medallion-safety-guards` (5 production safety guards), `airflow-dagster-interoperability` (TaskFlow + Astronomer Cosmos), and `ai-pipeline-incident-triage`.
  - **dbt & Data Quality Governance**: `dbt-transactional-microbatch` (dbt 1.9+ `microbatch` + `lookback` + SCD2 snapshots), `dbt-contracts-and-unit-tests` (`contract: {enforced: true}` + native `unit_tests:`), `dbt-duckdb-lakehouse-patterns` (`union_by_name=true`), and `great-expectations-openlineage-quality` (GX 1.3+ & OpenLineage blast radius).
  - **Data Modeling & MDM**: `sql-to-nosql-modeling` (with `scripts/audit_relational_schema.py`), `attribute-pattern-eav`, `polymorphic-schema-design`, `schema-evolution-versioning`, `extended-reference-optimizer`, `polyglot-persistence-strategy`, and `data-mesh-and-mdm-governance` (tripartite 2:1 accounting consolidation without data loss).
  - **Automation, Infra & Core**: `parallel-processing-patterns`, `docker-data-stack` (75% memory rule against OOM `exit 137`), `n8n-workflow-engineering` (stateless Hub-and-Spoke & static checks `S01..S05`), `ml-inference-pipeline-safety` (`sklearn.pipeline.Pipeline` serialization without `fit_transform` in production), `otel-pipeline-observability` (3-level OTel spans: `Module -> Process -> Operation`), `subagent-orchestration-patterns`, `knowledge-harvester`, and `skill-creator`.
- **MCP Catalog, Deployment Profiles & Production Playbook**:
  - Added `core/mcp/catalog.md` and `core/mcp/templates/data-eng-full.mcp.json` (`dbt-mcp`, `mcp-server-dagster`, `mcp-server-duckdb --read-only`, `mongodb-mcp-server`, `postgres-mcp`, `context7`).
  - Added `profiles/` (`core.json`, `data-eng-full.json`, `data-eng-mongodb.json`, `data-eng-lakehouse.json`, `data-eng-n8n.json`).
  - Added `core/playbooks/data-engineering-production-playbook.md` (`INC-01` through `INC-10`) and root `AGENTS.md`.

### Changed

- Upgraded `scripts/deploy-to-project.sh` to support `--target all|antigravity|claude|vscode` and `--profile <profile-id>` while preserving 100% backward compatibility with existing `.githubconfig/universal-ide-agents` submodule consumers.

- `docs/antigravity-consumption.md` — a comprehensive guide detailing how to integrate, configure, and consume these assets inside the Antigravity agentic environment, leveraging standard planning mode files and interactive slash commands (`/grill-me`, `/goal`, `/schedule`).
- Added walkthrough generation to the VS Code custom agent pipeline (`Feature Builder`), creating a matching `.github/sessions/{slug}/walkthrough.md` report at the end of delivery cycles for symmetric parity with Antigravity sessions.

- `scripts/deploy-to-project.sh` expanded to map and deploy Antigravity instructions files alongside VS Code custom assets, maintaining idempotency and dry-run safety. - `Feature Builder` orchestration streamlined: removed deleted subagents from core pipeline and updated orchestrator steps (Steps 3, 4, 5) to use native Copilot Plan/Agent Modes or Antigravity's Planning Mode directly with disk-based plan tracking (`.github/sessions/{slug}/plan.md`).
- `Planner` agent upgraded to absorb design self-validation constraints, acting as its own quality validator to check for duplication, portability, and naming convention compliance.
- `Reviewer` agent edit tool guidelines hardened to strictly prevent accidental repository asset edits (strictly limited to writing its own report).
- Corrected `docs/vscode-consumption.md` layout paths from `.config/` to `.githubconfig/` to reflect v0.1.1 rename convention.
- Added warning banner in both `.github/antigravity-instructions.md` and `.antigravity-instructions.md` to prevent future copy-drift.

### Removed

- **Removed `Plan Architect.agent.md`**: Delegated planning validation directly to native Copilot Plan Mode or manual verification.
- **Removed `Implementer.agent.md`**: Scoped execution rules directly into the `Feature Builder` orchestrator, transitioning implementation tasks to native Copilot Agent Mode or Antigravity's Planning Mode.

### Added

- `Documentation Steward` agent for source-control-aware updates to `README.md`, `CHANGELOG.md`, and conditional `LICENSE` maintenance.
- Session tracking infrastructure under `.github/sessions/` with an `index.md` trace file for historical context across Feature Builder runs.
- `scripts/deploy-to-project.sh` — canonical deployment script that distributes the full asset surface to consumer projects with explicit path mapping: `.github/` → `.github/`, `docs/` → `.github/docs/`, `scripts/` → `.github/scripts/`. Supports `--dry-run` to preview operations and `--clean` to remove files inside managed directories that no longer exist in the source. Automatically rewrites the hook command path in `context.json` after copying so it resolves correctly inside the consumer project. POSIX-compatible and idempotent.

### Changed

- `Planner` reworked: added `Explore` subagent for codebase research, structured four-phase workflow (Discovery → Alignment → Design → Refinement), session persistence to `.github/sessions/{slug}/plan.md` and `/memories/session/plan.md`, plan style guide, and handoff to `Implementer`.

- `Feature Builder` expanded to a nine-step workflow with session slug generation (step 0), `Documentation Steward` integration (step 6), and session index logging (step 9). Added `edit` tool.
- `Documentation Guidelines` prompt model updated to `GPT-5.4 (copilot)`.
- `README.md`, asset catalog, and VS Code consumption guide updated to reflect the deploy system, documentation stewardship workflow, and session tracking.
- `scripts/install-vscode-assets.sh` marked deprecated in favor of `scripts/deploy-to-project.sh`.
- Canonical submodule path renamed from `.config/universal-ide-agents/` to `.githubconfig/universal-ide-agents/` to avoid collision with `.config/` directories commonly used by Python, Node.js, and other project toolchains. Updated in `README.md`, `docs/vscode-consumption.md`, and the `deploy-to-project.sh` usage block.

### Fixed

- Corrected `user-invokable` → `user-invocable` in frontmatter of `Feature Builder`, `Plan Architect`, and `Reviewer` agents.
